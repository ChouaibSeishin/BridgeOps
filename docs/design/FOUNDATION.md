# Design foundation

Status: Phase 5.5 evolves the delivered UI into a light operations workspace with an intentionally dark graphite workflow canvas. Implementation/verification is in progress under the [UI audit and sequence](../development/PHASE_5_5_UX.md). Historical milestone notes below retain their scope. The existing [token source](../../frontend/src/styles/tokens.css), system fonts, Tailwind and current React Flow behavior remain the foundation.

Use a restrained operations workspace: warm neutral light surfaces, graphite dark surfaces, indigo actions, clear table hierarchy, monospaced identifiers and readable status text. Use system sans-serif initially to avoid font licensing/network dependencies. Typography targets: 14px body, 12px metadata, 24px page title; 1.5 body line height. Use a 4px spacing scale, 6–12px radii and modest shadows. Tokens govern colors, spacing, typography, borders, focus and states.

Implemented Phase 5.5 layout: a 240px contextual desktop rail and a native modal navigation drawer on smaller screens. Global Organizations, Workflows, Runtime and Account routes remain. Organization Operations contains authorized Workflows, Executions, Integrations and Support operations; Governance contains authorized Approvals, Automations & webhooks and Members & settings. Breadcrumbs and organization names come from actual route/access context. No separate Overview dashboard, AI, analytics, audit-query, search or notification destination is invented. Drawer keyboard containment, Escape and focus return are tested. Dense tables scroll within named keyboard-accessible regions.

Show page title, precise supporting text and one primary action. Prefer compact metric strips, tables and timelines over a grid of unrelated cards. Use outlined surfaces for configuration and inspection, not every content item. Status always includes text/icon, not color alone. Definition versions and operation IDs use monospace.

Workflow canvas: left categorized palette; central graphite graph with readable nodes/grid/edges and visible trigger/action/condition/approval distinctions; right light configuration inspector. Keep zoom/fit controls, keyboard alternatives to dragging, unsaved-change text, version badge and node-specific validation list. Errors navigate to the affected node. Publish shows the exact draft revision. Run published version remains a separate explicit action using the existing supported input and external-effects acknowledgement. The former draft TEST wording was target design; Phase 5.5 introduces neither TEST snapshots nor dry-run execution.

Execution view prioritizes persisted state and timestamps, then steps/timeline, attempts and sanitized item results. Approval view shows exact changes, requester, expiry, policy and consequences before decision; request approval and successful execution remain distinct. Future AI views must label MOCK or provider identity and distinguish proposal, approval request and completed action. They are not implemented by Phase 5.5.

Focus rings must be visible against both surface themes, pointer targets at least 40px (44px mobile), labels programmatically associated, and reduced-motion preference respected. Target WCAG 2.2 AA; no conformance claim before keyboard, contrast and assistive-technology checks. Minimum body text contrast is 4.5:1 and control boundaries/focus 3:1 where applicable. Tokens and component states require rendered validation.

Loading, empty, failure and success are separate states. Empty workflow list offers create only to authorized builders. Unavailable API displays retry and a correlation ID; no fabricated metrics. Disabled unavailable features explain the milestone dependency or are omitted. No inert primary navigation/action is shipped to imply functionality.

Implemented Phase 2 first editor uses accessible forms rather than the later canvas target above: registry-derived node configuration, explicit Next node connection selects, visible stable IDs, saved/unsaved revision, node/field error association and keyboard links. Add/remove operates on local unsaved definitions; Save persists through the authenticated API. Publish confirms the exact persisted revision; history shows actual version/hash/actor metadata with read-only exact snapshots. Duplication and archive are explicit actions, with archive preserving history. Existing warm-light/graphite-dark tokens, wrapping navigation and 40px/44px controls are retained. At that Phase 2 checkpoint there was no Run/Test Run control or execution state. Real-browser/visual verification is recorded separately after execution.

Phase 3 adds a functional persisted execution list/detail, confirmed internal-only start, optional bounded start delay, step/attempt/timeline inspection and current-authority cancel/eligible-retry controls. Active detail polling stops at terminal state or query failure; explicit refresh handles stale views. Friendly type/ordinal/config labels replace generated IDs in editor headings, connections and published inspection; technical IDs/JSON remain in collapsed accessible details. Ordinals follow graph edges with stable-ID fallback so canonical array ordering does not rename nodes. This is presentation-only: no node-name field, graph/schema/hash change or data migration. Browser evidence uses isolated real API/DB records, not fabricated metrics.
