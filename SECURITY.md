# Security reporting

No private vulnerability-reporting address, security-advisory channel or private maintainer contact has been configured or verified for this project. There is currently no documented private submission method. Do not post secrets, private exploit details or customer data to public issues.

Before public release the maintainer must configure a real private reporting method, verify receipt using a harmless test report, and replace this notice with its exact instructions. Until then, retain sensitive findings privately rather than assuming a channel exists. A public issue may request that a private reporting method be established, without including vulnerability details.

Reports, once a channel exists, should include affected commit, synthetic reproduction steps, observed/expected behavior and sanitized impact. Planned controls are not verified security properties. See the [threat model](docs/security/THREAT_MODEL.md) and [project status](docs/PROJECT_STATUS.md) for implementation evidence and limitations.
